Scrape, label, sample, induce, score

Each step publishes its rule. Only one of the six touches a language model, so a run never depends on one.

Deductive frame: rules, 100% coverage

A free tier token budget caps model labelling at a few dozen items per run. A brief that asks to quantify opportunity needs a denominator covering every item, not 6% of them. Every pattern is printed on /methodology.

Multi label on purpose

"wrong size delivered, return pickup never came"

FIT_SIZELOGISTICS_CX

Forcing one winner is how a fit signal disappears under logistics volume.

Inductive themes: model, stated sample

Groq proposes themes from the stratified sample. Shares are reported against the items it actually classified, and the run prints the rule and model agreement rate instead of assuming the rules are right.

04 · the score

Volume alone cannot win

Problem size is a weighted sum. The score is that size gated by leverage, so relevance to this goal decides the ranking.

Opportunity = 100 × Leverage × (0.50·Prevalence + 0.30·Severity + 0.20·Breadth)
0.50

Prevalence

Share of the corpus, normalised to the largest theme.

0.30

Severity

Share of rated items at 1 or 2★, with published fallbacks when ratings are thin.

0.20

Breadth

Platforms carrying it ÷ platforms in the run. All three means a category problem.

×

Leverage

0 to 1 per label. The inductive catch all is pinned to 0.

Four channels, honestly labelled

Data API v3, search plus comment threads. Free daily quota.

official · optional

sees: comments on videos

The shopper who saved something and never bought it leaves no trace in an app store review.

So the Channel Coverage panel prints each channel's measured share of items with a pre purchase signal, and the grounded Q&A box says "the excerpts don't cover this" instead of inventing an answer.
